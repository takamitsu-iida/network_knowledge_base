# RAG 利用ガイドライン (RAG Usage Policy)

本ナレッジベースを検索・活用し、AIに回答生成を行わせる際の運用基準を定義する。

## 1. 回答生成の原則 (Core Principles)

AIによる生成物は、必ず以下のステップを意識して生成させること。

1. **ドメインの特定:** 質問内容がどのドメイン（`01_network_domains/`）に属するかをまず特定する。
2. **階層的な参照:** 「概念 (Concepts)」→「実装 (Implementations)」→「制約 (Specs)」の順で参照し、情報を統合する。
3. **最新情報の優先:** `last_updated` が最新のファイルを優先的に参照する。
4. **根拠の明示:** 可能な限り、参照元となったファイルのパスやドキュメント名を回答に含めること。

## 2. 検索・生成時の制約 (Constraints)

AIが設計案やコンフィグを生成する際は、以下の制約を遵守させる。

- **機種依存の遵守:** `02_platform_specs/` に記載された制約事項（バグ、サポート範囲、コマンド差異）を優先する。もしテンプレート（01_implementations）と制約が矛盾する場合は、制約を優先すること。
- **命名規則の遵守:** デバイス名やインターフェース名は必ず `00_global_standards/naming_conventions.md` に従うこと。
- **採番ルールの遵守:** IPアドレス、VNI、AS番号の生成には `00_global_standards/addressing_policy.md` を適用すること。

## 3. 回答のバリデーション (Validation Workflow)

AIが生成した結果に対し、人間が行うべきチェックポイント。

1. **設定の整合性:** `03_projects/` 内の既存設定ファイルと IP や ESI が重複していないか。
2. **依存関係の確認:** 「前提条件」として挙げられている設定（Underlayなど）が完了しているか。
3. **最新パッチ情報:** 指定された OS バージョンが、その機能に対して推奨されているか。

## 4. プロンプト作成のお作法 (Prompt Engineering Tips)

AIに質問する際は、以下の情報を付与すると精度の高い回答が得られる。

- **役割の付与:** 「あなたは経験豊富なネットワークアーキテクトとして回答してください」
- **目的の明確化:** 「設計検討のため」「トラブルシュートのため」「設定作成のため」のどれか。
- **コンテキストの制限:** 「Catalyst 9000v の 17.18 バージョンに限定して回答して」と機器・OSを明示する。

---
## [運用上の注意]
- 本ナレッジベースにない未知の機能や、判断が難しい技術的な境界については、AIに推測させず、メーカーの公式マニュアルを参照することを強く推奨する。
- 最終的なコンフィグ投入前には、必ず人間による検証（ラボ環境での確認）を実施すること。
