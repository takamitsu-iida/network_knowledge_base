# EVPN VXLAN レイヤ2オーバーレイネットワーク 設計ガイド

## 1. 概要

本ドキュメントはEVPN VXLAN レイヤ2オーバーレイネットワークの設計理論を定義します。

次のような追加の機能を利用するには、本設計に加えて、別途追加の情報が必要になります。

- Q-in-VNI
- EVPN VXLAN Layer 3 Overlay Network
- IRB(Integrated Routing and Bridging)
- DHCP Relay in EVPN VXLAN
- VXLAN-Aware Flexible Netflow
- EVPN VXLAN QoS
- Optimized Layer 2 Overlay Multicast
- Tenant Routed Multicast
- EVPN VXLAN External Connectivity
- Private VLAN in a EVPN VXLAN
- EVPN VXLAN over IPsec
- EVPN VXLANv6
- Tenant Routed Multicast over EVPN VXLANv6
- EVPN Microsegmentation

## 2. 設計指針
- **冗長構成:** イーサネットセグメント方式によるマルチホーミングを基本とします。Anycast VTEP方式は対象外とします。

## 3. コンポーネント解説

### VXLAN
EVPN VXLANにおいて、VXLANはデータパケットをカプセル化し、レイヤー3ネットワーク上でトラフィックをトンネリングするための技術として使用されます。「MAC-in-UDP」のカプセル化を使用することで、レイヤー2オーバーレイネットワークを作成します。元のレイヤー2フレームにVXLANヘッダーが追加され、それがUDP-IPパケットの中に格納されます。VXLANオーバーレイネットワークは「VXLANセグメント」とも呼ばれます。同じVXLANセグメント内のホストデバイスや仮想マシン同士のみが、互いに通信を行うことができます。

### パケット構造
EVPN VXLANでLayer2オーバーレイネットワークを構成した場合、VXLANファブリック内を流れるパケットの構造は以下の通りです。

| レイヤ | フィールド | サイズ (Bytes) | 備考 |
| :--- | :--- | :--- | :--- |
| **L2** | **Outer Ethernet Header** | 14 | 送信先/送信元 MAC, EtherType |
| **L3** | **Outer IP Header** | 20 | 送信先/送信元 IP |
| **L4** | **Outer UDP Header** | 8 | 送信元/宛先ポート(4789), 長さ, チェックサム |
| **-** | **VXLAN Header** | 8 | VXLAN Flags(1), Reserved(3), VNI(3), Reserved(1) |
| **L2** | **Original Ethernet Header** | 14 | 元の MAC, EtherType |
| **Payload** | **Original Payload** | 可変 | 元のデータ (最大1500 - 50 = 1450) |
| **L2** | **Original FCS** | 4 | 元のフレームチェックシーケンス |

オーバーヘッドは、 **VXLANカプセル化による追加分** 14(Eth) + 20(IP) + 8(UDP) + 8(VXLAN) = **50バイト** となります。

VLANベースのLayer 2オーバーレイのとき、パケットにVLANタグは付きません。VLANとVNIが対応付けられるため、VXLANファブリック内でVLANタグを付ける必要がないためです。

一方、q-in-vniという技術を用いるときには、S-VLANとVNIがひも付きますので、運ぶパケットのVLANタグはそのまま保持されます。このときのオーバーヘッドはVLANタグが付与されることから **54** バイトとなります。

### MTU設計
VXLANファブリック内では元のパケットにVXLANのヘッダーが追加されるため、最低でも50バイト(VLANタグがあれば54バイト)が追加されます。したがってアンダーレイネットワークのMTUは1550バイトが最低ラインになります。ネットワークの設計としては、ジャンボフレームを有効化し、9100バイト以上に設定するのが推奨です。サーバが9000バイトで送信するとして、VXLANのオーバーヘッドで54バイト、余裕をみて9100バイト以上に設定します。ネットワーク機器はジャンボフレームの最大値付近のMTU 9216バイトを設定できるのであれば、それが最もトラブルが少ない設計になります。

[C9Kv IOS-XE 17の実装はここで確認](../02_platform_specs/00_iosxe_v17_evpn_vxlan.md)

### VXLANネットワーク識別子 (VNI)
各VXLANセグメントは、VXLANネットワーク識別子（VXLAN Network Identifier：VNI）と呼ばれる24ビットのIDによって識別されます。これにより、同一の管理ドメイン内に最大1,600万個のVXLANセグメントを存在させることが可能になります。

24ビットの範囲(0から16777215)のうち、装置の実装によっては一部が予約済みとして設定できないようになっています。VLAN番号として使われる範囲0-4095はVNIとしては使えなくなっているのが一般的です。

[C9Kv IOS-XE 17の実装はここで確認](../02_platform_specs/00_iosxe_v17_evpn_vxlan.md)

VLANベースのL2オーバーレイネットワークでは `10000 + VLAN番号` のように生成ルールを決める設計が推奨です。

### 仮想トンネルエンドポイント (VTEP)
すべてのVXLANセグメントには、仮想トンネルエンドポイント（Virtual Tunnel End point：VTEP）と呼ばれるトンネルエッジデバイスが存在します。これらのデバイスはVXLANネットワークのエッジに配置され、VXLANトンネルのインスタンス作成、およびVXLANのカプセル化とカプセル化解除を行う役割を担います。

VTEPは、ローカルLANセグメント上のスイッチインターフェイスと、トランスポートIPネットワークとやり取りするIPインターフェイスを備えています。

このIPインターフェイスは、トランスポートIPネットワーク上でVTEPを識別するための固有のIPアドレスを持っています。VTEPはこのIPアドレスを使用してイーサネットフレームをカプセル化し、そのカプセル化されたパケットをIPインターフェイス経由でトランスポートネットワークに送信します。また、VTEPデバイスは自身のVXLANセグメントに対するリモートのVTEPを検出したり、リモートのMACアドレスとVTEPのマッピング情報を自身のIPインターフェイスを通じて学習したりします。

このIPインターフェイスに付与するアドレスは、自身のループバックインタフェースのアドレスから採番することが推奨されます。またBGP用とVTEP用でループバックインタフェースを分ける設計が推奨されます。

### オーバーレイマルチキャスト
異なるVNI間の通信はレイヤ3のルーティングで行います。ユニキャスト通信であればVTEPがルータとして振る舞うことで実現できます。マルチキャストの場合はTRM（Tenant Routed Multicast：テナントルーテッドマルチキャスト）を使って、VNI間のマルチキャストトラフィックを効率的に転送します。

TRMはBGP-EVPNベースのソリューションで、VXLANの中に **「オーバーレイ専用のPIMドメイン」** を構築するようなものです。VTEPはどのVNIにどのマルチキャストの受信者がいるかを学習します（BGP EVPNを使用）。これにより、マルチキャストパケットが届いた際、VTEPが **「このパケットはVNI AからVNI Bへルーティングして転送すべきだな」** と判断できるようになります。

TRMを使用しない場合、マルチキャストトラフィックはアンダーレイネットワークの一部として、アンダーレイマルチキャストまたはイングレスレプリケーション（Ingress Replication）方式を用いたBUMトラフィック（Broadcast, Unknown unicast, Multicast）の形式で送信されます。これは単純なレイヤ2の延伸になるため、全VTEPにフラッディングされますし、別VNIにパケットを届けることはできません。

### アンダーレイ
アンダーレイネットワークとは、その上に仮想オーバーレイネットワークが構築される物理ネットワークのことです。オーバーレイネットワークとデータプレーンのカプセル化方式が定義されると、その下位にある物理ネットワーク全体でデータを移動させるための転送手法が必要となります。この転送手法が一般的に「アンダーレイトランスポートネットワーク」あるいは単に「アンダーレイ」と呼ばれます。

BGP EVPN VXLANにおいて、アンダーレイのレイヤー3ネットワークは、VXLANカプセル化されたパケットを送信元VTEPと宛先VTEPの間で転送し、それらの間の到達性（リチャビリティ）を提供します。VXLANオーバーレイと、VTEP間の基盤となるIPネットワークは、互いに独立しています。

VXLANの仕様としてはIPv6ネットワークもアンダーレイになりえますが、本設計ではアンダーレイはIPv4で構成します。

### EVPNコントロールプレーン
オーバーレイネットワークでは、どのデバイスがどのエッジデバイスの背後に存在するかを把握するメカニズムが必要です。VXLANは本来「フラッド＆ラーン（Flood and Learn）」方式で動作します。この方式では、特定のVXLANネットワーク内のブロードキャスト、不明なユニキャスト、およびマルチキャスト（BUM）トラフィックが、そのネットワークに参加しているすべてのVTEPに対してアンダーレイ経由で送信されます。ネットワーク上のトラフィック送信にはIPマルチキャストが使用されます。受信側のVTEPはパケットをカプセル化解除し、内部のフレームに基づいてレイヤー2のMACアドレス学習を行います。内部の送信元MACアドレスは、送信元VTEPに対応する外部の送信元IPアドレスと紐付けて学習されます。このようにして、戻りのトラフィックは学習済みのエンドホストに向けてユニキャストで送信されます。

「フラッド＆ラーン」方式の欠点は、VXLANネットワークにおいてスケーラビリティが確保できないことです。この問題を解決するために、MACアドレスの学習とVTEPの検出を管理するコントロールプレーンが導入されます。BGP EVPN VXLANの環境では、EVPN（Ethernet Virtual Private Network）がコントロールプレーンとして使用されます。EVPNコントロールプレーンは、MACアドレス情報とIPアドレス情報の両方を交換する機能を提供します。EVPNは、エンドポイントのMACアドレス、エンドポイントのIPアドレス、サブネットの到達性情報など、VXLANオーバーレイネットワークに関する到達性情報を配布するためのルーティングプロトコルとして、MP-BGP（Multi Protocol Border Gateway Protocol）を使用します。BGP EVPN配布プロトコルにより、トンネルエッジデバイスはロケーション・識別子マッピングデータベース（location-identity mapping database）内にマッピング情報を構築できるようになります。

### ルートターゲット (Route Target)
ルートターゲットは、マルチテナントネットワークにおけるルートの配布を制御する、EVPNルートアップデートに含まれる拡張属性です。EVPN VTEPは、すべてのVRFおよびレイヤー2仮想ネットワークインスタンス（VNI）に対して、インポートルートターゲット設定とエクスポートルートターゲット設定を持っています。VTEPがEVPNルートをアドバタイズする際、ルートアップデートに自身のエクスポートルートターゲットを付加します。これらのルートはネットワーク内の他のVTEPによって受信されます。受信側のVTEPは、ルートに含まれるルートターゲット値と、自身のローカルなインポートルートターゲット設定を照合します。両方の値が一致した場合、そのルートは受け入れられ、ルーティングテーブルに登録されます。一致しない場合、そのルートはインポートされません。取り込みたいインポートルートターゲットは複数指定できます。

名称が似ていて混同しやすいものにRD(Route Distinguisher)があります。RDは経路をユニークに識別するためのもので、通常は装置ごとに一つ、他の装置と重複しないように採番します。

### EVPNルートタイプ
EVPNコントロールプレーンは、以下の種類の情報をアドバタイズします。

- Route type1: イーサネット自動検出（Ethernet Auto-Discovery: EAD）ルートタイプです。イーサネットセグメント識別子（ESI）、イーサネットタグID、およびEVPNインスタンス情報をアドバタイズするために使用されます。EADルートのアドバタイズは、EVPNインスタンスごと、またはイーサネットセグメントごとに行われます。
- Route type2: エンドポイントの到達性情報をアドバタイズします。L2通信（MACアドレス学習）とL3通信（IP学習）の両方が含まれます。VTEPのMACアドレスおよびIPアドレスも含まれます。「MACアドレスXXはVTEP-Aにいるよ」「IPアドレスYYもVTEP-Aにいるよ」という情報を広めることで、ARP（Address Resolution Protocol）によるブロードキャストを減らす（ARP抑制）効果もあります。
- Route type3: どのVNI（L2 VNI）を扱っているか、そのVTEPアドレスをアドバタイズします。**BUMトラフィック（Broadcast, Unknown Unicast, Multicast）**をどこに転送すべきかのリストを作るために用いられます。VTEP同士で「ここにもVNI 100のグループがいるよ」と教え合うことで、VXLANのマルチキャスト（またはイングレスレプリケーション）経路を構築します。
- Route type4: イーサネットセグメントルートであり、イーサネットセグメント識別子、IPアドレス長、および発生元のルーターのIPアドレスをアドバタイズするために使用されます。
- Route type5: IPプレフィックス（サブネット、例: 192.168.10.0/24）およびそのサブネットに到達するためのL3 VNIをアドバタイズします。ホスト単位ではなく「サブネット単位」でルートを交換します。外部ネットワークや、別VRFへの通信をルーティングするために使われます。

#### L2オーバーレイ（EVPN VXLANでL2延伸を行う場合）で交換される経路
L2オーバーレイでは、以下の2つの経路を組み合わせて「L2ネットワークを仮想的に一つにつなぎます」。

##### 1. Route Type 2 (MAC/IP Advertisement Route) - 【主役】
L2オーバーレイにおいて、最も中心的な役割を果たします。既知の宛先に対する「効率的なユニキャスト転送（BGPによるMAC学習）」に利用します。

- 何を伝えるか:
    - MACアドレス: そのホストがどのVTEPの背後にいるか。
    - IPアドレス: (オプションですが、ARP抑制のために含めるのが一般的です)
- 役割:
    - MAC学習の代行: 従来ネットワークでは、スイッチがパケットをフラッディング（全ポートへ転送）してMACアドレスを学習していました。EVPNでは、このRoute Type 2をBGPで広めることで、物理的なフラッディングなしに「どのMACアドレスがどこのVTEPにいるか」という情報を全スイッチが把握できます。

##### 2. Route Type 3 (Inclusive Multicast Ethernet Tag Route) - 【BUM通信用】
未知の宛先やブロードキャストに対する「フラッディングの制御（VXLANトンネルを使ったレプリケーション）」に利用します。**「MACアドレスがまだ判明していない宛先」**や「ブロードキャスト・マルチキャスト」を処理するために必須です。

- 何を伝えるか:
    - そのVTEPがどのL2 VNIを保持しているかという情報。
- 役割:
    - BUM（Broadcast, Unknown Unicast, Multicast）トラフィックの転送: MACアドレスが未知の宛先へ送る際、どのVTEPにパケットをコピー（レプリケーション）すればよいかを決定するためのリストを作ります。






### EVPNインスタンス (EVI)
EVPNインスタンス（EVI）は、VTEP上の仮想プライベートネットワーク（VPN）を表します。これはレイヤー3 VPNにおけるIP VRFに相当するものであり、「MAC VRF」とも呼ばれます。

EVIは装置間で動的に交換される情報ではないため、ビット長は定義されていません。一般的には自然数で定義します。どの範囲の自然数を指定できるかは装置の実装に依存します。

[C9Kv IOS-XE 17の実装はここで確認](../02_platform_specs/00_iosxe_v17_evpn_vxlan.md)

### イーサネットセグメント (Ethernet Segment)
イーサネットセグメントは、VTEPのアクセス側インターフェイスに関連付けられており、ホストデバイスとの接続を表します。各イーサネットセグメントには、イーサネットセグメント識別子（Ethernet Segment Identifier: ESI）と呼ばれる一意の値が割り当てられます。あるホストデバイスが複数のVTEPに接続されている場合、これらの接続に対するESIは同一の値を設定します。

ESIはRFC 7432(BGP MPLS-Based Ethernet VPN) で定義されています。

- ESI 0はシングルホームサイトを表します
- ESI 0xFF FF FF FF FF FF FF FF FF FF (10バイトのFF)はMAX-ESIと呼ばれる予約された値です

ESIにはタイプがあります。先頭の1バイトはタイプを、続く9バイトで値を示します。ESI値を設計するときにはタイプと値の両方を決める必要があります。

- Type 0: オペレーターが管理する任意の9オクテットの値を示します
- Type 1: PEとCEの間でLACPが使用されている場合、このESIタイプは相手が通知するLACPパラメータから決定される自動生成ESI値を示します
- Type 2: PEとCEの間でスパニングツリーを有効にしたブリッジネットワークがある場合、このESIタイプはブリッジのパラメータから生成される自動生成ESI値を示します
- Type 3: 6バイトのMACアドレスと3バイトのLocal Discriminator値で構成されます。
- Type 4: 4バイトのルータIDと4バイトのLocal Discriminator値で構成されます（最後の1バイトは00固定です）
- Type 5: 4バイトのAS番号と4バイトのLocal Discriminator値で構成されます（最後の1バイトは00固定です）

Type 0はどの装置も実装されています。その他のタイプについては、利用する装置で何が実装されているかを確認する必要があります。

[C9Kv IOS-XE 17の実装はここで確認](../02_platform_specs/00_iosxe_v17_evpn_vxlan.md)

Type 0は9バイトを人間が指定することになります。

リーフAとリーフBが同じ装置とLACPで接続する場合、相手が通知してくるLACPのパラメータを元にESIを自動生成できるType 1を使うことで管理負荷の軽減、人的ミスの抑止ができます。

Type 3は装置のMACアドレス(6バイト) + 人間が指定する3バイトで構成されるため、バイト数が少ない分Type 0に比べると理解しやすいですが、管理負荷、人的ミスの観点ではType 0と変わりません。

ESIは、同じイーサネットを共有する場合のみ同じ値を設定し、それ以外はユニークである必要があります。管理台帳等で値が重複しないように管理しなければなりません。10バイトのESI値で管理するよりも、Typeが何で、9バイトの値が何、というように分けて管理した方がよいです。

装置にESI値を設定するときに、装置ローカルで管理する番号を用いることがあります。たとえばIOS-XEでは `l2vpn evpn ethernet-segment ローカル識別子` という設定コマンドを用いますが、ローカル識別子はESI値とは異なります（router ospf 1の1と同じイメージ）。あくまで装置ローカルなので他の装置と揃える必要はありませんが、同じL2ネットワークを構成する装置同士では揃えておいたほうがミス軽減になります。

### マルチホーミング
マルチホーミングにより、エンドホストデバイスをVXLANネットワーク内の複数のリーフスイッチに接続することが可能になります。カスタマー側ネットワークが単一のリーフスイッチに接続されるシングルホームトポロジーに比べて、ネットワークの冗長性が確保され、ネットワーク障害が発生した際のトラフィック中断を防ぎます。EVPNマルチホーミングは、シングルアクティブ（Single-Active）およびオールアクティブ（All-Active）の冗長モードで動作します。

装置によってはシングルアクティブしか実装されていないものもあり、利用する機器がどの方式を実装しているか、確認することが重要です。

[C9Kv IOS-XE 17の実装はここで確認](../02_platform_specs/00_iosxe_v17_evpn_vxlan.md)

#### シングルアクティブ
シングルアクティブの場合は、常に1つのVTEPだけがアクティブ（通信を担当する）構成です。エンド側との接続をイーサチャネルにしても、有効なメンバーポートは一つだけになります。そのため、シングルアクティブのときにはイーサチャネルは用いず、両方のリーフ装置に接続する構成にします。

#### オールアクティブ
オールアクティブの場合は、全てのVTEPが同時にアクティブ（通信を担当する）構成です。エンド側との接続はLACPでイーサチャネルを構成します。エンド側から受信する通信はイーサチャネルによって負荷分散されます。リモートVTEPから見ると、同じ宛先MACアドレスに対して中継先のネクストホップが2台見えるので、等コストマルチパスで負荷分散します。BUMトラフィックの場合は、両方のVTEPにパケットが届きますが、重複を避けるためにDF(Designated Forwarder)のみがエンド側にパケットを届けます。

### 統合ルーティング・ブリッジング (IRB)
EVPN VXLANは、統合ルーティング・ブリッジング（Integrated Routing and Bridging：IRB）機能をサポートしており、VXLANネットワーク内のVTEPがレイヤー2（ブリッジング）とレイヤー3（ルーティング）の両方のトラフィックを転送できるようにしています。VTEPがレイヤー2トラフィックを転送する場合、それはブリッジングを実行していると言われます。同様に、VTEPがレイヤー3トラフィックを転送する場合、それはルーティングを実行していると言われます。異なるサブネット間のトラフィックは、VXLANゲートウェイを経由して転送されます。

### VXLANゲートウェイ
VXLANゲートウェイとは、VXLANセグメント間、あるいはVXLAN環境から非VXLAN環境へとトラフィックを転送するネットワーク上のエンティティです。VXLANネットワーク内のリーフスイッチは、レイヤー2とレイヤー3の両方のVXLANゲートウェイとして機能できます。

レイヤー2 VXLANゲートウェイは、同一VLAN内のトラフィックを転送します。これは、VNIセグメントをVLANにマッピングすることで、VXLANとVLAN間のブリッジングを可能にします。

レイヤー3 VXLANゲートウェイは、異なるVLANへのトラフィックを転送します。これには「VXLAN間ルーティング」と「VXLAN-VLAN間ルーティング」の両方が含まれます。VXLAN間ルーティングは2つのVNI間のレイヤー3接続を提供し、VXLAN-VLAN間ルーティングはVNIとVLAN間の接続を提供します。

#### レイヤー2仮想ネットワークインスタンス (Layer 2 VNI)
VXLANオーバーレイネットワークを作成することで、複数のレイヤー3ネットワークによって隔てられたさまざまなリーフノードに接続されたホストデバイス同士が、単一のレイヤー2ネットワーク（VXLANセグメント）に接続されているかのように通信できるようになります。この論理的なレイヤー2セグメントは「レイヤー2 VNI」と呼ばれます。同一サブネット内の2つのVLAN間でレイヤー2 VNIを流れるトラフィックは、「ブリッジドトラフィック（ブリッジングされたトラフィック）」と呼ばれます。

VTEP上でローカルに定義されたVLANは、レイヤー2 VNIにマッピング可能です。ホストデバイスをレイヤー2 VNIに接続するには、接続先のVLANをレイヤー2 VNIにマッピングし、そのレイヤー2 VNIをVTEP上の論理インターフェイスであるNVE（Network Virtualization Edge）に関連付ける必要があります。

#### レイヤー3仮想ネットワークインスタンス (Layer 3 VNI)
レイヤー2 VNIに接続されたエンドポイントが、異なるIPサブネットに属するエンドポイントと通信する必要がある場合、トラフィックはデフォルトゲートウェイへ送信されます。異なるレイヤー2 VNIに属するエンドポイント間の通信は、レイヤー3ルーティング機能を介してのみ可能です。EVPN VXLANの展開において、ローカルVLANとグローバルなレイヤー2 VNIを組み合わせて定義された各レイヤー2セグメントは、通信のためにVRFに関連付けることができます。

レイヤー3 VNIは、VTEP上の各VRFに対してレイヤー3セグメンテーションを提供します。これは、ネットワーク内の各VRFインスタンスを一意のレイヤー3 VNIにマッピングし、VTEPの各レイヤー2 VNIを同じVRFに関連付けることで実現されます。これにより、特定のVRFインスタンス内で、レイヤー3 VNIを通じたVXLAN間通信が可能になります。VRFを使用して論理的なレイヤー3分離を実現する手法は「マルチテナンシー」として知られています。異なるサブネットの2つのVLAN間でレイヤー3 VNIを流れるトラフィックは、「ルーテッドトラフィック（ルーティングされたトラフィック）」と呼ばれます。

### モビリティ
BGP EVPNコントロールプレーンにおけるエンドポイントの識別は、そのMACアドレスおよびIPアドレスです。BGP EVPNは、VXLANオーバーレイ内でのエンドポイントのモビリティ（移動）をサポートするメカニズムを提供します。

VXLANファブリック内におけるエンドポイントモビリティについてはRFC 7432で規定され、通常はその仕様に基づいて実装されています。

#### MACモビリティおよび重複MAC検出
MACの移動（MAC Move）は、エンドポイント（またはホスト）があるポートから別のポートへ移動した際に発生します。新しいポートは、同じVLAN内の同一VTEP上にある場合もあれば、異なるVTEP上にある場合もあります。BGP EVPNコントロールプレーンは、MACルート（EVPNルートタイプ2）をアドバタイズすることで、このような移動を解決します。エンドポイントのMACアドレスが新しいポートで学習されると、そのホストが存在する新しいVTEPが（BGP EVPNコントロールプレーン上で）自身がそのホストのローカルVTEPであることをアドバタイズします。他のすべてのVTEPは、この新しいMACルートを受信します。

ホストは何度も移動する可能性があり、そのたびに対応するVTEPがMACルートをアドバタイズすることになります。新しいMACルートがアドバタイズされてから、古いルートが他のVTEPのルーティングテーブルから削除されるまでの間に遅延が生じ、一時的に2つの場所で同じMACルートが存在する可能性があります。ここで、「MACモビリティシーケンス番号」が、どのMACルートが最新であるかを判断する助けとなります。

ホストのMACアドレスが初めて学習されたとき、MACモビリティシーケンス番号は0に設定されます。値が0であることは、そのMACアドレスでモビリティイベントが発生しておらず、ホストがまだ元の場所にいることを示します。MACモビリティイベントが検出されると、エンドポイントが移動した先の（新しい場所にある）VTEPによって、新しいルートタイプ2（MACまたはIPアドバタイズメント）がBGP EVPNコントロールプレーンに追加されます。ホストが移動するたびに、新しい場所を検出したVTEPはシーケンス番号を1ずつ増やし、そのホストのMACルートをBGP EVPNコントロールプレーンでアドバタイズします。古い場所（VTEP）でそのMACルートを受信すると、古いVTEPは古いルートを削除します。

同一のMACアドレスが、異なる2つのポートで同時に学習されるケースが発生する場合があります。EVPNコントロールプレーンはこの状態を検出し、重複するMACが存在することをユーザーに警告します。重複MACの状態は、手動による介入、あるいは一方のポートでMACアドレスがエージングアウト（タイムアウト）した際に自動的に解消されます。

#### IPモビリティおよび重複IP検出
BGP EVPNは、MACモビリティをサポートするのと同様の方法でIPモビリティをサポートします。主な違いは、IPアドレスが（同じポートか別のポートかにかかわらず）異なるMACアドレス上で学習されたときに、IPの移動が検出される点です。重複IPアドレスは、同じIPアドレスが異なる2つのMACアドレス上で同時に学習されたときに検出され、これが発生した場合にはユーザーに警告が通知されます。
