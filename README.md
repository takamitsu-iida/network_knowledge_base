# Network Engineering Knowledge Base

本リポジトリは、ネットワーク設計・構築における技術情報およびパラメータを格納するナレッジベースです。
RAGシステムの参照先として構成されています。

## ディレクトリ構成詳細

### `00_global_standards/`
*   **用途:** 全ドメインで共通する設計指針。
*   **格納内容:** インターフェース命名規則、セキュリティポリシー、AS番号設計の考え方、共通ロゴ・ドキュメントテンプレート。
*   **AIの参照意図:** 「ネットワーク全体の設計基準を知りたい」「命名規則に基づいた名前を生成したい」という時に使用。

### `01_network_domains/`
機能ごとの技術的知見を集約したメインエリアです。
*   `{domain_name}/00_concepts/`
    *   **用途:** OSや機種に依存しない「技術の本質」。
    *   **格納内容:** 技術仕様（RFCの解説）、パケットの動作フロー、論理設計理論。
    *   **AIの参照意図:** 技術の「仕組み・なぜその設定が必要か」を理解したい時に使用。
*   `{domain_name}/01_implementations/`
    *   **用途:** 各OSでの設定作業（HOW-TO）。
    *   **格納内容:** CLIコマンド例、構成テンプレート、設定ステップ。
    *   **AIの参照意図:** 具体的な機器への「設定手順やコマンドコード」を構築・抽出したい時に使用。
*   `{domain_name}/02_platform_specs/`
    *   **用途:** 特定のプラットフォーム特有の「振る舞いと制限」。
    *   **格納内容:** 特定機種のバグ情報、メモリ/ライセンス制限、MTUの仕様、サポートされている機能リスト。
    *   **AIの参照意図:** 設定案が対象機種で「実行可能か」「注意点があるか」の検証（検閲）に使用。

### `02_projects/`
*   **用途:** 案件ごとの環境変数および設定値。
*   **格納内容:** サイト固有のIP設計、BGPネイバー情報、VLANリストなどを YAML形式で管理。
*   **AIの参照意図:** テンプレートに流し込むための「固有値（変数）」を読み取る時に使用。

---

## AI回答生成時の優先順位

回答生成時には以下のステップを推奨します：

1.  **前提理解:** `00_global_standards/` および `01_network_domains/*/00_concepts/` で該当機能の技術論理を確認する。
2.  **実装案作成:** `01_network_domains/*/01_implementations/` から対象OSの設定手順を抽出する。
3.  **制約チェック:** `02_platform_specs/` を参照し、抽出した設定案に機種固有の制限・注意点がないか確認する。
4.  **環境適応:** `03_projects/` 内の該当するYAMLから環境パラメータ（IP/VLAN等）を読み込み、最終的な構成案として統合する。
